Purpose: SCORE-08's "Save button checkpoints the game (PyMOL session + game-state sidecar)". Output: two gamestart functions + one wizard op + SMOKE-18.

**RECORDED DECISIONS (yolo):**
1. **cmd.save scope = FULL session (no selection argument), paired with a full-replace load (`cmd.load`, partial=0).** Rationale: SMOKE-17 proved the full-session save/load round-trip bit-exactly (the probe used plain `cmd.save()`); with a full-replace load, a game-scoped save would DESTROY the user's own objects on resume; settings/wizard blobs ride either way (exporting.py:442-455 runs all session-save tasks unconditionally). Faithful resume wins over leanness.
2. **Timer doctrine = capture elapsed BEFORE the file dialog; restore via rebase.** `elapsed_at_save` is the re-anchor authority; the wrapper (07-06) captures it pre-dialog; `capture_checkpoint_snapshot` stores it verbatim. On a game_over save, elapsed_at_save is None (final_time is frozen by stop_timer and authoritative).
3. **Save gating on a game_over state = ALLOW (no extra gate).** Rationale: GameState.to_dict carries game_over/end_state/final_time losslessly; the state round-trips as over/inert; refusing would need new wording and block legitimately archiving a finished game (07-RESEARCH-state.md §8.3 "allowing is simpler").
</objective>
