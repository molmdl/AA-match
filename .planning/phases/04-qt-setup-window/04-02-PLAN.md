<feature>
  <name>setup_form pure helpers</name>
  <files>aamatch/setup_form.py, tests/test_setup_form.py</files>
  <behavior>
Module contract: PURE (stdlib + `.setup_state` ONLY — no manifest import needed; manifest payload arrives as plain data). Docstring opens with the layer declaration in the wizard_text.py style ("Layer: PURE ... unit-testable under bare python3.6 ... registered in tests/test_purity.py PURE_MODULES"). NEVER mention the tokens `get_model`, `matrix_reset`, `get_object_ttt` (PROSE_PIN discipline, test_code_audit.py).

`build_state(form_values, known_set_ids=()) -> dict`:
- `form_values` is a plain dict carrying the 7 setup fields as the widgets collect them PLUS one non-schema key `upload_ready` (bool: True iff the window holds ingested content matching the form's upload path). All inputs plain data — the pure layer never reads files.
- Raises ValueError (user-facing message, % -format) BEFORE validate_state on:
  1. `source_mode == 'upload'` and not `upload_ready` → "upload mode needs an ingested molecule file -- use Browse to pick an SDF or MOL2 file first (uploads are not stored in setup files)"
  2. `source_mode == 'demo'` and `demo_set_id` non-empty and `demo_set_id` not in `known_set_ids` → "demo set %r is no longer bundled -- pick a set from the dropdown" (message names the id)
- Pops `upload_ready`, calls `validate_state(form_values)` (the single validation authority — never widget-side re-validation), THEN raises on:
  3. normalized `interaction_mode in ('exclusive', 'block_exclusive')` and normalized `allowed_interactions` empty → message wording aligned with the generator's own refusals (generator.py:386-389 / :399-401): for exclusive "exclusive mode requires the setup field 'allowed_interactions' to be non-empty -- check the interactions the game should teach in Setup"; for block_exclusive "block_exclusive mode requires 'allowed_interactions': no interactions checked". Rationale: this fires BEFORE start_game's cleanup (gamestart.py:239), so a doomed start never deletes the prior game objects.
- Returns the validate_state-normalized dict, unmodified otherwise. validate_state never fails on the mode/allowed pair (it silently normalizes, setup_state.py:115-135) — the pre-checks above are the only new refusals.

`usable_randomized_state(seed=None, demo_set_id='') -> dict`:
- `state = randomize_state(seed)` then `state['demo_set_id'] = demo_set_id` (a real manifest id or '' = all sets) and return. Nothing else changes: source_mode stays 'demo', upload stays None (setup_state.py:157-159), the random allowed/mode/int fields are untouched. Do NOT modify randomize_state's own output shape (pinned by tests/test_setup_state.py).

`manifest_sets(payload) -> list`:
- Input: a parsed manifest PAYLOAD (dict with 'sets'); output: list of `(set_id, title, tier)` tuples sorted by set_id, where title falls back to set_id and tier falls back to '' when missing (.get defaults — payload shape manifest.py:31-43). Empty/missing 'sets' → empty list (parse already accepts empty manifests, STATE 02-03). No I/O.
  </behavior>
  <implementation>
Stdlib imports: `copy` only if needed (avoid mutating the caller's dict — build a new dict for validate_state input). Pure sibling import: `from .setup_state import validate_state, randomize_state`. No manifest import (payload is passed in as data — matches manifest.py's own no-I/O discipline for callers). House %-format, no f-strings, python3.6 syntax floor (Gate D compiles it).
  </implementation>
</feature>
