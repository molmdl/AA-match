<feature>
  <name>Versioned container core + atomic JSON I/O</name>
  <files>aamatch/persistence.py, tests/test_persistence.py</files>
  <behavior>
Module constants: `AAM_MAGIC = "AAMATCH"`, `FORMAT_VERSION = 1`,
`KINDS = ('setup', 'level_spec', 'game', 'checkpoint')`,
`class FormatError(ValueError)`.

Testable cases (write ALL as failing tests first):

1. `make_container('setup', {'a': 1})` → exactly `{'magic': 'AAMATCH', 'version': 1, 'kind': 'setup', 'data': {'a': 1}}`.
2. `make_container('bogus', ...)` → FormatError mentioning `kind`.
3. `check_container(make_container('setup', d), 'setup')` → returns the container dict unchanged.
4. Foreign: `check_container({'nope': 1}, 'setup')` → FormatError whose message contains `not an AA-match file`.
5. Newer: `check_container({'magic': AAM_MAGIC, 'version': 999, 'kind': 'setup', 'data': {}}, 'setup')` → FormatError containing both `unsupported` and `Please update AA-match`.
6. Misfiled: container with kind='level_spec' checked as 'setup' → FormatError containing `expected an AA-match setup file`.
7. Older: container with `version: FORMAT_VERSION - 1` → NO exception (refuse-newer/accept-older policy, prior-art B3).
8. Corrupt version field: `version: 'abc'` → FormatError with a clear message (not a bare int() crash).
9. `write_json_atomic` + `read_json_file` round-trip: nested dict with unicode strings and boundary ints → exact `==` equality after load (NEVER assertAlmostEqual).
10. Non-JSON garbage file → `read_json_file` raises FormatError containing `could not parse AA-match JSON`.
11. Atomicity — no litter: after a successful write, the target dir contains no files matching `.aam_*.tmp`.
12. Atomicity — failure simulation: with `unittest.mock.patch('os.replace', side_effect=OSError('boom'))`, `write_json_atomic` over an EXISTING file raises OSError, the original file content is UNCHANGED, and no `.aam_*.tmp` litter remains.
13. NaN refusal: payload containing `float('nan')` → ValueError (from `allow_nan=False`), not silent non-standard JSON.
14. Byte-stability: two `write_json_atomic` calls with equal dicts → file bytes identical (read with `'rb'` and compare).
15. `save_container(path, 'setup', d)` / `load_container(path, 'setup')` round-trip returns `data` equal to `d` (container transparent to caller).
  </behavior>
  <implementation>
Follow research R2/R3 sketches exactly (01-RESEARCH-pure-foundation.md):

- `make_container(kind, data)`: validate `kind in KINDS` else `FormatError`; return the 4-key dict.
- `check_container(raw_dict, expected_kind)`: (1) magic mismatch → `FormatError("not an AA-match file (magic=%r, expected %r)")`; (2) version parse: `try: version = int(d.get('version')) except (TypeError, ValueError): raise FormatError("missing or invalid version field in AA-match file")`; (3) `version > FORMAT_VERSION` → `FormatError("unsupported AA-match format version %d (expected <= %d). Please update AA-match.")`; (4) `kind != expected_kind` → `FormatError("expected an AA-match %s file, found kind=%r")`. Version < current is ACCEPTED (document in docstring: additive-only evolution, readers use .get defaults — prior-art B3/B4 semantics).
- `write_json_atomic(path, obj)`: `payload = json.dumps(obj, indent=2, sort_keys=True, allow_nan=False)`; `data = payload.encode('utf-8')`; `fd, tmp = tempfile.mkstemp(dir=os.path.dirname(os.path.abspath(path)) or '.', prefix='.aam_', suffix='.tmp')`; write bytes, `os.fsync(fd)`, `os.close(fd)`; `os.replace(tmp, path)`; on ANY exception: best-effort `os.remove(tmp)` (guard with try/except OSError), then re-raise.
- `read_json_file(path)`: `open(path, 'rb')` → `json.loads(bytes)` (3.6 loads accepts bytes — env fact A5); JSON failure → `FormatError("could not parse AA-match JSON: %s" % exc)`.
- `save_container(path, kind, data)` = `write_json_atomic(path, make_container(kind, data))`; `load_container(path, expected_kind)` = `check_container(read_json_file(path), expected_kind)['data']`.
- Purity: module-level imports stdlib ONLY (`json, os, tempfile`) + docstring stating the purity contract (prior-art B7 phrasing). NO pymol/Qt/numpy import at module level OR inside any function body.
- Do NOT add setup/level-spec specific wrappers here (they land in 01-05/01-06 — this plan stays kind-agnostic). Do NOT add header checksums (R2 rationale: hand-editable educator files are a feature).
  </implementation>
</feature>
