<feature>
  <name>Backup pure core over injected stores</name>
  <files>aamatch/backup.py, tests/test_backup.py</files>
  <behavior>
Module shape: `class BackupError(Exception)`; store protocol (duck-typed):
`save_bytes(key, data: bytes)`, `load_bytes(key) -> bytes`,
`delete(key)`, `exists(key) -> bool`. Implementations: `MemoryStore`
(dict-backed) and `FileStore(root_dir)` (save via temp file +
`os.replace`; idempotent delete; `exists` via `os.path.exists`).
Functions: `snapshot(store, key, payload)` → manifest dict
`{'key': key, 'sha256': <hex>, 'timestamp': <float>}`;
`verify_intact(store, key, current_payload)` → bool;
`restore(store, key)` → payload dict; `discard(store, key)` (idempotent).
Constant `BACKUP_OBJECT_PREFIX = '_aam_backup'` (documented for the future
cmd-tier adapter; underscore = private-object convention, prior-art E2).

Canonical form: `_canonical(payload) = json.dumps(payload, sort_keys=True, allow_nan=False).encode('utf-8')`.

Testable cases (write ALL as failing tests first — run against BOTH stores via subTest or a store-fixture list):

1. snapshot → restore round-trip: `restore(store, key) == payload` (exact dict equality, nested dicts + unicode).
2. snapshot returns a manifest with `key` == key, a 64-char lowercase-hex `sha256`, and a float `timestamp`.
3. verify_intact True when current_payload equals the snapshotted payload; False when ANY nested value differs.
4. restore on a missing key → BackupError with message containing `no backup` (caller asserts, never re-derives — P7 discipline; document in docstring).
5. verify_intact on a missing key → BackupError (same discipline as prior-art E3's CmdException trap).
6. discard removes the backup; second discard does NOT raise (idempotent, prior-art E2); after discard, restore raises BackupError.
7. snapshot over an existing key REPLACES it (snapshot → mutate payload → snapshot again → restore returns the SECOND payload — stale-backup discard semantics, prior-art E2).
8. **Corruption simulation (the load-bearing test, PITFALLS.md:181):** with FileStore → snapshot → flip one byte in the stored file on disk (read bytes, XOR one byte, write back) → `restore` raises BackupError containing `backup corrupt` AND `verify_intact(store, key, original_payload)` returns False.
9. Same corruption simulation against MemoryStore (tamper the stored bytes directly via the store's internal mapping or `save_bytes` with garbage) → restore raises BackupError.
10. Canonical determinism: `_canonical({'b': 1, 'a': 2}) == _canonical({'a': 2, 'b': 1})` (key order irrelevant).
11. FileStore atomic save: after save_bytes, `root_dir` contains no leftover temp files (prefix `.aam_`).
12. FileStore round-trip across instances: `FileStore(dir)` snapshot → a NEW `FileStore(dir)` instance restores the same payload (persistence on disk).
  </behavior>
  <implementation>
Follow research R6 exactly:

- `snapshot`: `data = _canonical(payload)`; `store.save_bytes(key, data)`; return manifest with `hashlib.sha256(data).hexdigest()` and `time.time()`.
- `verify_intact`: missing key → `raise BackupError("no backup stored under key %r" % key)`; return `store.load_bytes(key) == _canonical(current_payload)`.
- `restore`: missing key → BackupError(`no backup ...`); `data = store.load_bytes(key)`; if `len(data) < 64` or `sha256(data[64:]).hexdigest() != data[:64].decode('ascii')` → hmm — NO: keep the sha in the SEPARATE manifest returned by snapshot, and have restore/verify recompute from... Actually simplest verifiable design: store `sha256hex + b'\n' + data` as the stored bytes (self-describing): `restore` splits on the first newline; recomputed sha mismatch → `raise BackupError("backup corrupt (sha256 mismatch) for key %r")`; else `json.loads(data)` (JSON failure → BackupError `backup corrupt (unparseable)`). `verify_intact` recomputes the SAME way and returns False instead of raising (after the missing-key check which raises, matching case 5).
- `discard`: `store.delete(key)` — delete is idempotent by store contract.
- `FileStore.save_bytes`: `tempfile.mkstemp(dir=self.root, prefix='.aam_', suffix='.tmp')` → write → fsync → close → `os.replace(tmp, os.path.join(self.root, key))`. Create `root` with `os.makedirs(root, exist_ok=True)` in `__init__`. `delete`: `try: os.remove(path) except OSError: pass`. Keys are simple filenames (validate: no `os.sep` in key — raise BackupError otherwise; keeps paths safe).
- Purity: module-level imports stdlib only (`hashlib, json, os, tempfile, time`) + purity docstring (prior-art B7 phrasing). NO pymol anywhere, including function bodies.
- Do NOT implement the cmd-tier adapter (object snapshotting via cmd.create) — that lands in a later phase; this module only defines policy + stores. Keep `BACKUP_OBJECT_PREFIX` as a documented constant for it.
  </implementation>
</feature>
