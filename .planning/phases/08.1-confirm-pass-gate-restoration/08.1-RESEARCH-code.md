## Detection mechanics

**How confirm computes formed/missing today** — `engine.detect_molecule(level_index, molecule_index)` (`engine.py:458-489`):
1. `geometry.extract_game_atoms()` — one iterate_state pass over the `_aam_`-prefixed objects (cmd-tier, geometry.py)
2. filter to the molecule's ligand object + its slot objects (:481-485 — the 03-06 cross-molecule guard; the wrong partner is absent by construction)
3. `_remap_ligand_bonds(records, [lig_object])` (:486; helper at :160-187 — the 02-09 probe-pinned position→id remap)
4. `detector.detect(records, lig_bonds)` — the 7-type surface
5. `game_state.records_for_molecule(found, slot_objects, lig_object)` post-filter (:488-489; `game_state.py:91-124` — belt-and-braces attribution pin)

Return: the canonically sorted scoped record list. Each record is a plain dict carrying at minimum `'type'` (one of the 7 `INTERACTION_TYPES`), `'aa'`/`'lig'` object/id dicts, and type-specific metrics. **Score/formed are derived PURELY from `r['type']`** (`game_state.py:score` :65-88 consumes `r['type']` only; `_formed_types` :127-141 dedupes by type in canonical order).

**Is the pass gate a pure predicate over data already at hand? YES.** At wizard.py:829 the impl holds `records` (the scoped set) and `required` (:828). The pass rule is a function of exactly these two plain-data values:

- mode `'any'` (items `[]`, generator.py:396): passing = ≥1 record of any type ⇔ `score(required, records) == 1.0`
- mode `'list'` (items `[{'type': t, 'count': 1}]`, types UNIQUE — `derive_required` generator.py:398-439: block_exclusive emits the checked set, unset emits `rng.sample` without replacement; count always 1, generator.py:376-379): passing = every item type present in the record types ⇔ `score(required, records) == 1.0` (binary-per-item: `formed == len(items)`)

**Float-exactness note:** `score` returns `formed / float(len(items))` for list mode — when `formed == len(items)` this is exactly `1.0` (IEEE integer-values division), and any deficit gives `< 1.0`; 'any' mode returns literal `0.0`/`1.0`. So `score(...) == 1.0` (or `>= 1.0`) is an EXACT threshold, no epsilon needed — and it reuses the SCORE-01 truth function as the single "formed" home. The equivalent set-form (`all(item['type'] in record_types ...)`) is what `score` already computes internally.

**What the failed debrief needs** is already computed in the impl: `score` (the would-be value), `formed` (canonical-order formed type names), `required`, `extras` (:840-853). `wizard_text.result_lines(score, formed, required, extras)` (:106-175) renders the full Formed/Missing debrief verbatim — including the pinned 'Formed: (none)' and 'Nothing formed (score 0.00)' shapes. **Zero new rendering logic is required for the panel surface.**

## CONFIRM_PASS_RULE home decision (with rationale + purity analysis)

**Decision: `aamatch/game_state.py` — module constant `CONFIRM_PASS_RULE = 'all'` beside a pure predicate (suggested name `confirm_passes(required, results)`), both next to `score()` (:65-88).**

Rationale, against every candidate:

| Candidate | Purity | Verdict |
|---|---|---|
| `game_state.py` (PURE_MODULES #13, imports only `time` + `.setup_state`) | pure; already gated by `tests/test_purity.py`; **already owns the SCORE-01 "formed" truth** (`score`, `_formed_types`) | ✅ the single semantic home; WSL-unit-testable in `tests/test_game_state.py`; zero PURE_MODULES registration churn |
| `wizard_core.py` (PURE #14) | pure but **ZERO-import by documented style** (module docstring :6-7, :45) and it has NO formed-semantics — the predicate would re-implement `score()`'s item walk (single-home violation) | ❌ duplicates the truth function |
| `status_text.py` / `wizard_text.py` | pure but TEXT builders — a game-rule constant in a wording module is a layer violation | ❌ wrong layer |
| `engine.py` | cmd tier (`from pymol import cmd` at module level, engine.py:120) — **never WSL-importable**, violating the "predicate unit-testable in WSL" constraint; Gate D only compiles it | ❌ not unit-testable |
| `setup_state.py` / `level_spec.py` | pure but they own setup/schema vocabularies, not gameplay rules | ❌ wrong module |

**Suggested predicate shape** (one-line flip per CONTEXT constraint 2):

```python
CONFIRM_PASS_RULE = 'all'   # 'all' = every required interaction formed (spec pass-gate);
                            # 'any' = at least one required interaction formed (documented alternative)

def confirm_passes(required, results):
    """The Confirm pass gate (Phase 8.1): CONFIRM_PASS_RULE read over the
    SCORE-01 truth function. 'all' -> score == 1.0 (exact: 'list' formed
    == len(items) divides to exactly 1.0; 'any' is binary). 'any' ->
    score > 0.0. Reuses score() so the gate and the recorded score can
    never disagree (single "formed" home)."""
    value = score(required, results)
    if CONFIRM_PASS_RULE == 'all':
        return value >= 1.0
    if CONFIRM_PASS_RULE == 'any':
        return value > 0.0
    raise ValueError('confirm_passes: unknown CONFIRM_PASS_RULE %r'
                     % (CONFIRM_PASS_RULE,))
```

(Under `'any'` the two modes coincide in 'any'-required mode and 'any' relaxes 'list' to ≥1 formed — the documented alternative's meaning. Fail-closed on an unknown rule, house style.)

**Gate call-site — the single choke point.** The gate DECISION is pure (game_state); the gate ENFORCEMENT point must be the one place both Confirm surfaces flow through: `_confirm_molecule_impl`, between `detect_molecule` (:829) and `record_scored` (:831). Two law-consistent wirings for the planner to choose:

- **(A) Wizard calls the pure predicate directly:** lazy `from . import game_state` (wizard.py already imports pure siblings — `setup_state` at module level :82); `if not game_state.confirm_passes(required, records): <failed branch>`. Minimal diff. Tension: wizard.py module-docstring contract 1 says "NO scoring, NO spec knowledge here" — mitigated because the RULE lives in the pure layer and the wizard only branches on the verdict (it already computes `score`/`formed` for the debrief).
- **(B) Thin engine op** (e.g. `engine.confirm_verdict(level, molecule, required, records)` returning `{'passed', 'score', 'formed'}`): keeps the wizard a pure router (contract 1 strongest reading) and mirrors the 06-03 "front door in the engine" precedent. Slightly larger diff; engine.py is Gate-D-compiled only, so the op must stay a thin delegate over the pure predicate.

Both keep ONE enforcement site. **What must NOT happen:** the gate inside `engine.record_scored` (Skip shares it — skip must record unconditionally), inside `engine.confirm` (no production caller — the wizard path would stay blind), or in BOTH the wizard and an engine op (two sites).

## Failed-confirm contract design

**Requirement recap (CONTEXT constraint 3 + human directive):** NO record (no `molecule_scores` entry, no `skip_count` change), NO advance, debrief (Formed/Missing — SCORE-02 feedback) + a clear not-passing/retry line, timer keeps running, retry freely.

### Return shape through `_guard` — must be a TRUTHY dict, never None

`None` through the `_guard` seam means "guarded refusal" and the tab short-circuits: `game_window.py:635-636` (`if result is None: return None`) — **the sync `_refresh_status()` at :637 would never run**, so a None return cannot deliver the info-box debrief. Option (a) in the research brief (falsy/None result) is therefore WRONG for a failed confirm. **Design: return a truthy dict, additive over the 06-05 shape** (all existing consumers use `.get`):

```python
{'passed': False,            # NEW — the gate verdict
 'score': <would-be float>,  # the detection preview, NOT recorded
 'total': <unchanged float>, # engine.total_score() — provably unchanged (see Score semantics)
 'advanced': None,           # no advance happened
 'game_over': False,         # the game cannot end on a failed confirm
 'summary': None,
 'level_pos': <current 1-based>, 'molecule_pos': <current 1-based>}
```

**Downstream safety, proven at the two consumers:**
- `_confirm_now` (:637): truthy → `_refresh_status()` runs → the failed-confirm debrief reaches the info box through the SAME poll channel as the scored debrief. :638 `result.get('game_over')` is False → `_endgame_sequence` NOT called. ✔
- `_on_confirm` (:610): `result and result.get('game_over')` → False → **`cmd.refresh()` + the 100 ms `_show_endgame_modal` singleShot schedule NOTHING** (the 06-09 law "a None/falsy guarded result schedules nothing" extends naturally to a non-game_over truthy result — the condition already keys on `game_over`, game_window.py:610). ✔ A failed confirm on the LAST molecule cannot fire the endgame modal.
- Panel path: `confirm_molecule()`'s return is discarded by PyMOL's PParse execution; the panel/prompt re-render (:869 `cmd.refresh_wizard()`) is the panel-side feedback.

### The two debrief surfaces

1. **Wizard panel + prompt (the Phase-3 restore):** on failure set `self._result = {'score': float(score), 'formed': list(formed), 'required': required, 'extras': extras}` + `self._error = None` + `cmd.refresh_wizard()` — exactly the 1c3737c statements. `wizard_text.panel_entries` (:220-225) and `prompt_lines` (:257-261) already render `result_lines` from `state['result']` — **dormant path, zero wizard_text changes**. The player sees 'N/M required interactions formed (score x.xx)' / 'Formed: …' / 'Missing: …' and STAYS.
   - Lifecycle of `_result` on the retry cycle: a subsequent PASS advances → `_rebind_maps` (:532) clears `_result` (the D3 law holds on the pass path — `st['result'] is None` post-advance, smoke_15 B2:530-533 keeps passing). A subsequent SKIP advances → same clear. A repeated failed confirm overwrites `_result` with fresh numbers. `reset_grid` clears it (:984). No new clearing site needed.
2. **Game-tab info box:** the poll is the only channel that serves BOTH surfaces with parity (the panel path bypasses the tab impl entirely — a handler-logged line in `_confirm_now` would be tab-only and break the CONTEXT constraint-5 tab+panel parity). The marker mechanism (`_set_event` → `status_events` fingerprint :414-427 → `_EVENT_BUILDERS` dispatch) therefore needs **a NEW event kind** (suggested `confirm_failed`) with a new pure builder in `status_text.py`, e.g. a header ('Molecule %d of %d not passing yet — score so far %.2f (total %.2f).' — exact wording is the planner's) + `result_lines(...)` reused verbatim (the single-home law) + a retry line ('Form the missing interactions and Confirm again.'). Skip/Give-Up warnings stay untouched.

### Hard coupling the planner must plan for

`status_text.status_events` **raises ValueError on an unknown marker kind** (:417-423, fail-closed closed set) — the raise happens inside `_refresh_status`, i.e. inside the tab's sync refresh AND the 1 Hz tick. **Adding the `_set_event('confirm_failed', ...)` stamp without adding the kind to `EVENT_KINDS` + `_EVENT_BUILDERS` in the SAME change breaks the poll at runtime** (a failed confirm would crash the tick). EVENT_KINDS grows 15 → 16; the "EVENT_KINDS pinned exactly 15" law (STATE.md 05-01/07-03) is a recorded test evolution (`tests/test_status_text.py:314/324` pin the kind set; :843 pins the vocabulary), same class as the Phase-6 reserved-kinds landing. The pinned `molecule_scored` payload shape is NOT reused — the new kind carries its own payload (do NOT stamp `molecule_scored` for a failed confirm: its builder's header says "scored", and a scored marker without a record would lie against the one-record invariant).

### What a failed confirm must NOT do (negative contract)

- NOT call `engine.record_scored`/`score_current`/`record_molecule_result` → `molecule_scores`, `score_per_molecule`, `formed_types_per_molecule` untouched → the one-record guard stays untripped → **retry freely** (and Skip-after-failed-confirm works).
- NOT touch `skip_count`/`giveup_count`.
- NOT call `_advance_after_record`, `_sync_end_state` (nothing ended), or any timer op.
- NOT set `self._error` (an ERROR line is the house-refusal channel; a failed confirm is routine gameplay feedback — and the error channel's sticky dedupe, status_text.py:438-441, would swallow a repeated identical retry message anyway).

## Score semantics

**When confirm PASSES:** the recorded score is `score(required, records)` evaluated at confirm time — under `CONFIRM_PASS_RULE = 'all'` a pass means `score == 1.0` EXACTLY in both modes (see Detection mechanics), so **every passing confirm records exactly 1.0**. The 02-10 "detection-at-confirm-time partial score" survives only on the SKIP path (partial scores come exclusively from skips now) — which is precisely the original spec decision ("Score = fraction of required interactions formed, binary per interaction; skip stores partial score", PROJECT.md via STATE.md seeded decisions) and the Skip-redundancy smell test in the 08-11 diagnosis. Under the documented `'any'` flip, a pass could record a partial list-mode score (formed ≥ 1 but not all) — the one-line-flip semantics must be documented in the constant's comment.

**When confirm FAILS:** the `score` in the debrief is the WOULD-BE value (the detection preview — what `result_lines` renders as '(score x.xx)'). It must be labeled as not-recorded in the new marker builder's wording (e.g. 'score so far' / 'not recorded'). The code provably cannot shift the running total: `total_score` is `sum(self.molecule_scores)` (`game_state.py:201-204`), and a failed confirm appends nothing to `molecule_scores` (record_molecule_result is the ONLY appender — `game_state.py:298`, reached only via `score_current` :543 ← `record_scored` :590 / `confirm` :555; the failed branch calls none of them). `total` in the failed return dict is read AFTER the gate would have recorded — read it from `engine.total_score()` as today (:834) or omit it; either way it equals the pre-confirm total.

**Endgame arithmetic under the gate:** `endgame_summary`'s completed-law (`game_state.py:355-360`) demands `n_records == total_molecules` for 'completed'; records now originate ONLY from passes (1.0 each) and skips (partial). Level scores (`:374-396`) aggregate the keyed store — a failed confirm contributes nothing, so per-level sums and the total are pass/skip-only by construction. The CONTEXT persistence check ("SMOKE-17/18/19/20 — molecule_scores only from passes/skips") is satisfied structurally, not just by smoke.
