<feature>
  <name>game_file upload helpers: split, supply, read, row build/validate</name>
  <files>aamatch/game_file.py, tests/test_game_file.py</files>
  <behavior>
All additions to the existing pure module (04-03). New constants: `UPLOAD_MAX_RECORDS = 50` (Decision 8; perf rationale in the refusal message: new_game temp-loads every candidate row upfront, engine.py:220-223 -- one extraction per record per Generate).

`split_sdf_records(text) -> list of str`:
- Split at lines exactly `$$$$` (the SDF terminator; pymol-src/modules/chempy/sdf.py:145-155). Each returned record INCLUDES its trailing `$$$$` line. Lines are split preserving original line endings via `text.splitlines(True)` then re-joined per record (never str.split('\n') -- CRLF byte-stability, persistence.py binary-mode rationale). Trailing whitespace-only tail after the last `$$$$` is dropped. A text with no `$$$$` returns [text] if it has non-whitespace content (single-record SDF is legal), else [].

`split_mol2_segments(text) -> list of str`:
- Split at lines starting with `@<TRIPOS>MOLECULE` at column 0 (writer keyword, pymol-src/modules/chempy/mol2.py:34). Each segment INCLUDES its `@<TRIPOS>MOLECULE` line; any leading comment/pre-block lines before the FIRST keyword are attached to the first segment (the C reader's restart mechanism consumes segment 1 -- research multi_record_rules). No keyword found -> [text] if non-whitespace else [].

`check_upload_supply(records, fmt, source_name) -> None`:
- records = list of record strings from a split. Refusals (ValueError family; FormatError is the natural home -- these are file-shape problems): empty list -> "upload %r contains 0 %s records -- nothing to play with"; any record whose stripped text is empty -> "upload %r record %d is empty -- remove it and retry"; len(records) > UPLOAD_MAX_RECORDS -> "upload %r carries %d records -- the v1 cap is %d (generation temp-loads every molecule per generate); split the set or reduce it".
- Returns None silently when the supply is usable.

`read_upload_source(path) -> (text, sha256_hex, fmt)`:
- fmt from the LOWERCASED extension (`os.path.splitext`); not in FORMATS ('sdf','mol2', manifest.py:65) -> FormatError "unsupported upload format %r (expected .sdf or .mol2) -- PDB is not supported (no reliable bond orders)".
- Read binary; `sha256_hex = hashlib.sha256(raw).hexdigest()` (the FILE hash -- Decision 19 contrast: row hashes are over record text).
- Decode utf-8 strict; UnicodeDecodeError -> FormatError "could not decode %r as UTF-8".
- Return (text, sha256_hex, fmt). Pure I/O exactly like persistence.read_json_file (stdlib open only).

`build_uploaded_row(atom_records, lig_bonds, profile, record_text, fmt, index) -> dict`:
- The 14 manifest keys (manifest.py:68-73) plus one extra 'title' (original record title line if parseable, else '').
- entry_id = 'mol-%03d' % (index + 1) (generator's own convention, generator.py:852); file = 'uploads/mol-%03d.%s' % (index + 1, fmt) (synthetic package-relative-style key -- matches the manifest forward-slash convention; never a real path); format = fmt; sha256 = sha256(record_text.encode('utf-8')).hexdigest(); protonation = 'as-recorded' (never invent claims -- PITFALL 14); atom_count = len(atom_records); heavy_atom_count = count of records with elem != 'H'; bond_count = len(lig_bonds); bond_order_counts = tally of `capability._bond_order_int(order)` over lig_bonds (digit-string keys -> positive ints, manifest.py:278-295 shape); formal_charge_sum = sum of formal_charge over atom_records (missing key counts 0); states_expected = 1; metal_present = profile['has_metal']; halogen_present = profile['has_halogen_donor']; size_class = `generator._candidate_class({'heavy_atom_count': heavy})` (single home for the bucket thresholds SIZE_S1/S2, generator.py:578-596).
- Same-package private imports are deliberate (single-home law beats import purity): `from .generator import _candidate_class`, `from .capability import _bond_order_int`.

`validate_uploaded_rows(rows) -> None`:
- For each row: non-empty set_id == UPLOAD_SET_ID and entry_id asserted by construction but CHECKED anyway (fail-closed); then delegate to the manifest's own dict-level entry rules via a thin same-package call into `manifest._check_entry`-family logic (manifest.py:191-295) -- or, if the private call shape makes that awkward, re-invoke the exact per-key checks through a small local adapter that CALLS manifest's functions (never re-implements the rules). Explicit absolute-path refusal reusing manifest.py:267-275's rules (backslash / absolute / drive-letter file values refused -- the os.path.join hazard).
- Returns None on success; raises ValueError-family with the manifest's own message shapes on failure.
  </behavior>
