## 2. The movement execution path end-to-end

All op bodies follow one skeleton. Citing `nudge_cam` as the canonical path:

1. **Entry + fail-closed guard:** `nudge_cam(dx, dy, dz)` (wizard.py:668-675) → `self._guard(self._nudge_cam_impl, float(dx), float(dy), float(dz))`. `_guard` (wizard.py:640-653) catches **ValueError-family only** (EngineError / PlacementError / WizardError) → sets `self._error = str(e)` + `cmd.refresh_wizard()`, returns None; unexpected exceptions PROPAGATE (bug surfacing).
2. **Game-over gate:** `_require_playing()` is the FIRST line of every gameplay impl (wizard.py:655-666; the 06-06 "one game-over gate home" law, STATE.md:212) — raises `WizardError('The game is over.')` when `engine.is_over()`. 5. **R^T conversion (pure):** `wizard_core.view_camera_to_world` (wizard_core.py:135-163): `view[0:9]` = row-major world→camera R; world step = R^T·step — `world_x = r00*sx + r10*sy + r20*sz` etc. (wizard_core.py:161-163). NOTE the docstring's pin (wizard_core.py:34-37): *"the R^T convention is live-verified against a scripted cmd.set_view; if the live build proves the opposite convention, this function is the single fix site."* Live verification executed by SMOKE-07 :449-469 (scripted Rz(90°) block; dev 2.51e-08 recorded STATE.md:135).

7. **THE FROZEN BAKE FORMS** (wizard.py module docstring contract 5, wizard.py:56-72 + comment block :579-589):
   - translate: `cmd.translate(v, obj, state=1, camera=0)` — wizard.py:685-686.

This is THE PLAY-02 invariant: on-screen == stored == detected by construction.

## 3. Start-composition framing code — `aamatch/gamestart.py`

The start/advance composition is ONE seam: `compose_molecule_view(registry, molecule_index=0)` (gamestart.py:366-390) = `_move_ligand_in_front` → `_frame_ligand_above_grid` → `cmd.zoom(_active_molecule_selection(...), buffer=5.0)`. Called by `start_game` (gamestart.py:475) and `start_game_from_payload` (:543), and by the wizard lifecycle after every molecule/level advance via `_compose_active_molecule` (wizard.py:560-566 — the 06-04/06-10 seam).

**(a) The camera roll — `_frame_ligand_above_grid` (gamestart.py:231-289).** CAMERA-ONLY composition; no game object moves:
- Reads `view = list(cmd.get_view())` (:249), ligand/grid rows from `geometry.extract_game_atoms()` filtered to the ACTIVE molecule's objects (:250-257).
- Computes camera-space x/y of the ligand centroid vs grid centroid via **R rows 0/1 dotted with (p − view[9:12])** (`cam_x`/`cam_y` helpers :266-274).
- Degenerate guard: `h = hypot(sx, sy)`; `if h < 1.0e-8: return` (grid↔ligand axis along the sight line) (:279-281).
- **THE ROLL: `phi = math.atan2(-sx, sy)`** ("roll: ligand->up, centered-x") (:282), then rows 0/1 of R are rotated in place (:284-288: `view[0+i] = c*r0[i] + s*r1[i]; view[3+i] = -s*r0[i] + c*r1[i]`), then `cmd.set_view(view)` (:289). Row 2 (the depth axis) and all non-R fields are untouched — this is why the front-offset cam-z lead survives (:329-331) and why `cmd.zoom` afterwards preserves R exactly ("element delta 0.0", :115-119).
- Fail-soft: empty lig/grid rows → return, keep the plain zoom view (:258-259).

**(b) The ligand front-offset — `_move_ligand_in_front` (gamestart.py:292-363).** GEOMETRY-side world translate of the ligand object (`cmd.translate([need*view[6], need*view[7], need*view[8]], lig_name, state=1, camera=0)` :362-363) so its centroid leads every own-grid atom by ≥ `_FRONT_LEAD = 5.0` Å (constant :165-171) along cam-z.
