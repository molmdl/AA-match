## 0. Production facts the pins depend on (read-verified)

These determine WHERE the gate goes and what each pin must become.

### 0.1 The current confirm chain (the defect site)

`aamatch/wizard.py:825-873` `_confirm_molecule_impl`:

1. `self._require_playing()` (:827 — the 06-06 game-over gate, stays)
2. `records = engine.detect_molecule(self._level_index, self._molecule_index)` (:829-830)
3. `score, formed = engine.record_scored(...)` (:831-833) — **records unconditionally**
4. `advanced, summary = self._advance_after_record()` (:861 — the ONE advancement site, :793-823)
5. `self._set_event('molecule_scored', ...)` (:863-868 — the marker)
6. returns `{'score', 'total', 'advanced', 'game_over', 'summary', 'level_pos', 'molecule_pos'}` (:870-873 — the 06-05 pinned dict)

Both Confirm surfaces route through this ONE op: the wizard panel button
(`'Confirm': 'cmd.get_wizard().confirm_molecule()'`, pinned in tests/test_wizard_text.py:183)
and the Game tab (`game_window.py:634` `result = prior.confirm_molecule()` inside
`_confirm_now`). **⇒ ONE gate site inside `_confirm_molecule_impl` (between detect and
record_scored) covers panel AND tab. No other advance path exists**: `_advance_after_record`
is called only from `_confirm_molecule_impl` (:861) and `_skip_molecule_impl` (:911);
`engine.advance_molecule`/`advance_level` are called only from `_advance_after_record` plus
direct smoke drives of the engine ops (SMOKE-15 PART A — engine-primitive probes, not the
player path).

### 0.2 Why the gate CANNOT live in `engine.record_scored`

`engine.record_scored` (engine.py:560-591) is the shared record primitive for Confirm AND
Skip (`engine.skip_molecule` :594-610 calls it). The pass gate must gate CONFIRM only
(Skip is "the non-passing advance path by construction" — CONTEXT constraint 4). Putting
the gate in `record_scored` would gate Skip too. The 06-03 law also pins that
`score_current`/`engine.confirm` stay byte-identical detection probes
("smoke_04/06/07 legitimately re-score molecule (0,0) as detection probes", engine.py:571-574
docstring). **⇒ the gate site is the wizard impl + a PURE predicate.**

### 0.3 The pure predicate home

`game_state.py` already owns the scoring semantics: `score(required, results)` (:65-88 —
'any' binary :77-78; 'list' = formed-items/items :79-85) and `_formed_types` (:127-141).
`game_state` IS in `PURE_MODULES` (tests/test_purity.py:99-104) — a `CONFIRM_PASS_RULE`
predicate added there needs **zero purity-registry changes** and is WSL-testable directly.
Semantics: rule `'all'` in 'list' mode = every required item's type formed ⇔ `score == 1.0`;
in 'any' mode = ≥1 record (the mode's own binary). Rule `'any'` (documented alternative) in
'list' mode = ≥1 required item formed — a genuinely different predicate, hence the
single-homed constant per CONTEXT constraint 2.

### 0.4 The failed-confirm debrief machinery already exists and is pinned

Phase-3 commit `1c3737c` (verified via `git show 1c3737c:aamatch/wizard.py:516-541`):
`_confirm_molecule_impl` did `engine.confirm(...)` → `self._result = {'score', 'formed',
'required'}` → `cmd.refresh_wizard()` — detect + render + STAY (no record, no advance).
The rendering builder `wizard_text.result_lines(score, formed, required, extras)` 
(aamatch/wizard_text.py:106-175) is intact and pinned by tests/test_wizard_text.py (53
tests): list mode renders `'N/M required interactions formed (score x.xx)'` + `'Formed:
...'`/`'Formed: (none)'` + `'Missing: ...'`; 'any' mode renders `'Interaction formed
(score 1.00)'` or `'Nothing formed (score 0.00)'`. `wizard_text.panel_entries` consumes
`state['result']` (:220-224). **The failed-confirm debrief = set `_result` (Phase-3
verbatim) + a not-passing/retry line; zero new rendering machinery strictly required.**

### 0.5 The tab's game_over transition is end-path-agnostic (PART F mechanism)

`game_window.py:_refresh_status` :519-520: `prev_go = bool(prev.get('game_over')) ... if

### 0.6 The proven passing-pose recipes (for making confirms genuinely pass)

## 2. Per-pin rework design

### 2.0 The two viable designs (planner decision)

**Design A — keep the DEFAULT seed-42 game, type-agnostic placement helper.** Write ONE
smoke-level helper `form_required(wiz)` that reads the CURRENT molecule's required items +
required slots from `engine._payload`/`_registry` and dispatches per interaction type to a
construction recipe (pi_stacking: §0.6; h_bond/salt_bridge/hydrophobic/cation_pi:
distance+geometry translates; halogen/metal: §0.6 probe geometry ADAPTED to the slot
object). Pros: the default game (and its 3×2 shape literals) stays. Cons: **4-6 new
per-type recipes must be built, verified, and kept float32-stable** — the largest new
surface in the phase, and the probe's raw-fragment constructions (§0.6) prove geometry but
NOT slot-object adaptability. Required types for seed 42 are unknowable ahead of the first
run (§0.7) — recipe development would be iterative inside expensive 120-240 s smoke runs.

**Design B — re-game the drives to a block_exclusive ['pi_stacking'] game (RECOMMENDED).**
Switch the confirm-dependent drives (SMOKE-15 PART B/C, SMOKE-16 A3/A7/C/F) to
`start_game(setup=validate_state({'interaction_mode': 'block_exclusive',
'allowed_interactions': ['pi_stacking'], 'molecules_per_level': 2, 'difficulty_levels':

## 7. Danger audit

- **D1 — Vacuous "fresh zeros" after rework (real, found).** SMOKE-16 B4 :691-:698 and
  SMOKE-19 B5 :470/B6 :487 assert fresh zeros AFTER a restart/import — their teeth exist
  only because B2/B4 accrued a REAL record beforehand. If the blind confirms are merely
  deleted (rather than converted to skips or passing confirms), those asserts pass
  trivially (0 == 0) and the replace-vs-fresh distinction is untested. **Mitigation: the
  skip conversion (§2.3/§2.4) — it accrues a record, keeping the teeth.**
- **D2 — Camera-compose law downgrade (real).** If B2's rework settles for a skip-driven
  advance, the CONFIRM-specific compose teeth (the 06-10 human-reported defect) weaken —
  the compose is shared (`_advance_after_record`), but the check's named intent is the
  confirm advance. **Mitigation: keep B2 a PASSING CONFIRM drive (Design B §2.1).**
- **D3 — One-record refusal interplay (real, must be pinned).** After a FAILED confirm,
  `has_record` must stay False — a retry (passing confirm) and even a subsequent SKIP must
  both work without tripping the 06-03 refusal. New-pin §3.2 item 7. Conversely the
  reworked C1 pairing must not double-record (the guard text would surface mid-drive).
- **D4 — PART F path loss (real).** If F2's final op becomes a skip, the panel-confirm
  natural-end path loses its only headless coverage and the 9870561 trio would be pinned
  only for skip/give-up ends. **Mitigation: §4 — F2 stays a PASSING panel confirm.**
- **D5 — Timer-freeze invariant (must be pinned).** The failed confirm must not touch
  `timer_anchor` (timer keeps running — CONTEXT 3). Nothing in the current impl touches it
  pre-advance, but the pin must exist (§3.2 item 6) so a future refactor can't silently
  freeze or reset the clock on failure.
- **D6 — `advanced` key ambiguity (design risk).** If the failed return reuses
  `advanced: None` (the game-complete value), any future consumer keying on
  `advanced is None` alone misreads a failure as completion. B5 :643 is safe (it also
  asserts game_over True), but the planner should prefer a distinct signal (§3.3).
- **D7 — test_code_audit exposure on smoke edits (mechanical, verified gate).** New smoke
  code must not add `cmd.get_model`/`matrix_reset`/`get_object_ttt` calls or TOKEN-PAIR
  nested atom loops (tests/test_code_audit.py scans smoke/). Use the sanctioned
  pick+rotate_axis+move_to recipe (§0.6); `placement.transform_baked` is legal in
  ENGINE-tier smokes (SMOKE-04 precedent) but banned in wizard game paths
  (wizard.py:583-586) — Design B drives are wizard-tier, so rotate_axis it is.
- **D8 — C7 literal drift (fragility).** Hand-recomputing 'Total score: X.XX' strings is
  fragile if the drive's pass/skip mix changes again. Prefer deriving the expected block
  from `status_text.endgame_lines(summary_c)` (already done for the block) and computing
  the numeric literals from the drive's known placements at runtime.
- **D9 — 'Molecules completed: 6 of 6' assumption (verify at build).** The reworked C-drive
  mixes skips and passing confirms; `molecules_completed` must still count 6 (skips record).
  Read of endgame_summary semantics supports it; the reworked smoke verifies it live.
